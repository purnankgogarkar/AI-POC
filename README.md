# AI-POC — P² Suite

Four independent working prototypes exploring predictive, advisory AI workflows across different business domains — HR, finance, operations, and sales — all built on synthesized data with a shared design language ("P²" branding: violet, teal, amber, and cobalt accents on a common neutral palette, dark/light theming throughout).

Each app is fully self-contained (its own `package.json`, its own seeded dataset) and runs independently — there's no shared backend or database between them.

| App | Folder | What it does |
|---|---|---|
| **P² Retain** | [`hr-retention/`](hr-retention/) | Group-level workforce retention risk, driver factors, and retention recommendations. |
| **P² Verify** | [`finance-tax-recovery/`](finance-tax-recovery/) | Invoice tax validation against jurisdiction rules — recovery opportunities and audit exposure. |
| **P² Assemble** | [`steel-production-planning/`](steel-production-planning/) | Production package pre-population with a planner workbench and exception triage. |
| **P² Focus** | [`sales-intelligence/`](sales-intelligence/) | Predictive, holistic sales pipeline prioritization for regional sales leadership. |

## Running an app

```bash
cd <app-folder>
npm install
npm run seed   # regenerates that app's synthetic dataset deterministically
npm run dev
```

Each defaults to `http://localhost:3000` — pass `-- --port 3001` (etc.) to run more than one at once.

## Design principles across the suite

- **Synthesized data only.** Every dataset is generated by a seeded script (`npm run seed`) and committed to that app's `data/` folder — reproducible, and reviewable by just opening the JSON.
- **Transparent scoring, not black-box ML.** Every risk/priority score is a documented, hand-specified formula (see each app's `lib/scoring.ts`), chosen so any number can be hand-verified. The point of these prototypes is the workflow and UX, not model accuracy.
- **Advisory, not autonomous.** No app takes an automated action against a system of record. Every workflow ends in a human decision — approve, release, resolve, investigate.
- **No backend.** Interactive state (resolved exceptions, uploaded records, theme choice) lives in the browser's `localStorage`, scoped per app.

## Stack

Next.js (App Router) + TypeScript + Tailwind CSS + shadcn/ui (Radix/Base UI primitives) + Recharts + `next-themes`, per app.
